# เว็บไซต์งานวิชาการ โรงเรียนหนองหานวิทยา

Next.js 15 + Supabase (ฐานข้อมูล/ล็อกอิน/เก็บไฟล์) deploy บน Vercel
รูปแบบ **C — ครบวงจร**: ส่วนสาธารณะ + ส่วนครู (ล็อกอิน) + หน้าจัดการเนื้อหา `/admin`

## ขั้นตอนติดตั้ง (ใช้อีเมลของฝ่ายวิชาการ)

ทำทุกขั้นตอนด้วยบัญชีอีเมลกลางของฝ่ายวิชาการ ไม่ใช่อีเมลส่วนตัว เพื่อให้ฝ่ายถือกรรมสิทธิ์ระบบ

### 1) Supabase
1. สมัคร/ล็อกอิน <https://supabase.com> ด้วยอีเมลฝ่ายวิชาการ → **New project** (ภูมิภาค Singapore)
2. **SQL Editor** → วางเนื้อหาไฟล์ `supabase/schema.sql` ทั้งไฟล์ → **Run**
   (สร้างตาราง สิทธิ์ RLS ที่เก็บไฟล์ `academic-docs` และข้อมูลเริ่มต้น)
3. **Project Settings → API** คัดลอก `Project URL` และ `anon / publishable key`
4. **Authentication → Providers → Email** เปิดใช้งาน; ปิด “Allow new users to sign up” หากไม่ต้องการให้คนทั่วไปสมัครเอง แล้วสร้างบัญชีครูที่ **Authentication → Users → Add user**
5. สร้างบัญชีแอดมินคนแรก (ใช้อีเมลฝ่ายวิชาการ) แล้วตั้งสิทธิ์ใน SQL Editor:
   ```sql
   update public.profiles set role = 'admin' where email = 'อีเมลฝ่ายวิชาการ@...';
   ```

สิทธิ์ (`profiles.role`): `guest` (ล็อกอินได้แต่ยังไม่เห็นเนื้อหาครู) · `teacher` (เห็นเอกสาร/บริการเฉพาะครู) · `editor` (เพิ่ม/ลบเนื้อหา) · `admin`
อีเมลโดเมน `@nonghanwit.ac.th` ได้สิทธิ์ `teacher` อัตโนมัติ — อีเมลอื่นเริ่มเป็น `guest`

### 2) รันในเครื่อง (ไม่บังคับ)
```bash
cp .env.example .env.local   # ใส่ค่าจาก Supabase
npm install
npm run dev                  # http://localhost:3000
```
ถ้ายังไม่ใส่ `.env.local` เว็บยังเปิดได้ด้วยข้อมูลโรงเรียนตั้งต้น (ส่วนข่าว/เอกสารจะว่างจนกว่าจะเชื่อม Supabase)

### 3) Vercel
1. สมัคร/ล็อกอิน <https://vercel.com> ด้วยอีเมลฝ่ายวิชาการ
2. อัปโหลดโค้ดนี้ขึ้น GitHub (บัญชีฝ่ายวิชาการ) → Vercel **Add New → Project** → เลือก repo
3. ใส่ Environment Variables: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `NEXT_PUBLIC_ACADEMIC_EMAIL` (ไม่บังคับ)
4. **Deploy** — ได้ลิงก์ `*.vercel.app` (ผูกโดเมนของโรงเรียนภายหลังที่ Settings → Domains)
5. กลับไป Supabase → **Authentication → URL Configuration** ใส่ Site URL เป็นลิงก์ Vercel

หรือใช้ CLI: `npm i -g vercel && vercel --prod`

| ข้อ | ฟังก์ชัน | ที่อยู่ |
|---|---|---|
| 1 | แก้ไขรายการเดิม (ข่าว เอกสาร ปฏิทิน ฯลฯ) | `/admin/<ตาราง>` → ปุ่ม “แก้ไข” |
| 2 | เผยแพร่/ซ่อน (ฉบับร่าง) และตั้งเวลาลงข่าว (ตั้งวันที่ล่วงหน้า) | `/admin/news` |
| 3 | อัปโหลดรูปภาพจากหน้าแอดมิน (ข่าว ผลงาน) และไฟล์เอกสาร | ฟอร์มใน `/admin/...` |
| 4 | จัดการผู้ใช้/กำหนดสิทธิ์ (admin เท่านั้น) | `/admin/users` |
| 5 | คำร้องออนไลน์ + ติดตามสถานะด้วยรหัส + หลังบ้านตอบคำร้อง | `/requests` · `/admin/requests` |
| 6 | ติดตามการส่งงานครู (ครูแจ้งส่ง, ฝ่ายวิชาการดูภาพรวม, ข้อความแจ้งเตือนไว้วางใน LINE) | `/tracking` · `/admin/tracking` |
| 7 | ตารางสอนตามห้อง/ตามครู | `/timetable` |
| 8 | ประกาศห้องเรียน + ตรวจผลสอบรายบุคคล (รหัสนักเรียน + PIN) | `/classes` · `/results` |

**โหมดเดโม:** ถ้ายังไม่ตั้งค่า Supabase (`.env.local` ว่าง) เว็บจะเข้าโหมดเดโมอัตโนมัติ — ใช้ข้อมูลตัวอย่างในหน่วยความจำ
และมีแถบสีเหลืองด้านบนให้สลับมุมมอง ผู้เยี่ยมชม / ครู / editor / แอดมิน เพื่อสาธิตสิทธิ์ต่าง ๆ (รีสตาร์ตแล้วข้อมูลรีเซ็ต
ตัวอย่างตรวจผลสอบ: รหัส `10001` PIN `1234` · ตัวอย่างติดตามคำร้อง: `RQ-69-DEMO01`)

**เมื่อพร้อมใช้งานจริง:** รัน `supabase/schema.sql` แล้วรัน `supabase/schema_v2.sql` ต่อ (สร้างตารางใหม่ + สิทธิ์ RLS + ฟังก์ชันตรวจสถานะคำร้อง/ผลสอบ)
ใส่ค่า `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` โหมดเดโมจะปิดเอง

**ข้อควรระวังเรื่องข้อมูลส่วนบุคคล (PDPA):** ผลสอบรายบุคคลและคำร้องมีข้อมูลส่วนบุคคล — ใช้ PIN ที่เดายาก (6 หลักขึ้นไป)
แจ้งนักเรียนเป็นรายบุคคล และเก็บเท่าที่จำเป็น · ภาพที่อัปโหลดในโหมดเดโมเก็บชั่วคราวเท่านั้น

## บัญชีครูด้วยเลขบัตรประชาชน (v3)
แอดมินเพิ่มครูได้ที่ `/admin/users` (ทีละคนหรือวางรายชื่อจาก Excel) — ครูล็อกอินด้วย **เลขบัตร 13 หลัก** + รหัสผ่านเริ่มต้น **วันเกิด พ.ศ. ววดดปปปป** (เช่น 15042530) แล้วระบบบังคับเปลี่ยนรหัสผ่านครั้งแรก
1. รัน `supabase/schema_v3.sql` ใน SQL Editor (ต่อจาก schema.sql และ schema_v2.sql)
2. ตั้ง env (Vercel → Settings → Environment Variables และ `.env.local`): `SUPABASE_SERVICE_ROLE_KEY` และ `NATIONAL_ID_SECRET` (ดู `.env.example`) แล้ว Redeploy
3. **เลขบัตรไม่ถูกเก็บในฐานข้อมูล** — ระบบแปลงเป็นค่าแฮช HMAC ด้วย `NATIONAL_ID_SECRET` เก็บเป็นอีเมลภายใน และเก็บเฉพาะ 4 หลักท้าย (`profiles.id_hint`) ให้แอดมินแยกบัญชี · **สำรอง `NATIONAL_ID_SECRET` ไว้** หากหายหรือเปลี่ยน ครูจะล็อกอินด้วยเลขบัตรไม่ได้ (ต้องรีเซ็ตรหัส/สร้างบัญชีใหม่)
4. ครูลืมรหัส → แอดมินกด “รีเซ็ต…” ที่แถวของครูใน `/admin/users` (ต้องใส่วันเกิดอีกครั้ง) · ครูเปลี่ยนรหัสเองได้ที่ `/account/password`
5. ควรกำชับให้ครูเข้าระบบเปลี่ยนรหัสผ่านภายในไม่กี่วัน เพราะระหว่างนั้นเลขบัตร+วันเกิดคือข้อมูลที่คนใกล้ชิดเดาได้
6. อีเมลแอดมินกลางเดิมยังล็อกอินด้วยอีเมลในช่องเดียวกันได้

## ปฏิทินรายเดือน / ประวัติแก้ไขคำร้อง / แถบบัญชี (v4)
- **ปฏิทิน** `/calendar` แสดงเป็นตารางรายเดือน กิจกรรมเป็นแถบสี (คร่อมหลายวันได้ ถ้ามีเกิน 3 รายการต่อวันจะขึ้น “+n เพิ่มเติม”) คลิกแถบหรือคลิกวันเพื่อดูรายละเอียด · เพิ่ม/แก้กิจกรรมที่ `/admin/events` ตามเดิม
- **ประวัติการแก้ไขคำร้อง** บันทึกทุกครั้งที่ editor/admin เปลี่ยนสถานะหรือข้อความตอบกลับ (ใคร · วันเวลา · ค่าเดิม→ค่าใหม่) ดูได้ที่การ์ดแต่ละคำร้อง หรือแท็บ “🕘 ประวัติการแก้ไข” ใน `/admin/requests` · **ต้องรัน `supabase/schema_v4.sql`** (ตารางเป็นแบบเพิ่มอย่างเดียว และชื่อผู้แก้ถูกประทับโดยฐานข้อมูลจากบัญชีที่ล็อกอิน)
- **แถบบัญชีที่ใช้งานอยู่** แสดงที่ขอบล่างของทุกหน้าเมื่อล็อกอิน: ชื่อ · สิทธิ์ · บัญชี (เลขบัตรลงท้าย 4 หลัก หรืออีเมล) พร้อมปุ่มเปลี่ยนรหัสผ่าน/ออกจากระบบ
- **เมนู “คำร้อง”** เลื่อนเมาส์ไปที่ปุ่มจะขึ้นรายการประเภทคำร้อง (คลิกแล้วเปิดฟอร์มที่เลือกประเภทไว้ให้), ติดตามสถานะ และลิงก์จัดการ/ประวัติสำหรับ editor

## ส่งงานครูผ่าน Google Drive + แบบแจ้งส่ง (v5)
- ครูกรอกแบบแจ้งส่งที่ `/submit` (งานที่ส่ง · กลุ่มสาระฯ · รายวิชา · ระดับชั้น · ห้อง · ภาคเรียน · หมายเหตุ) แล้วแนบไฟล์ — **ไฟล์ไปที่ Google Drive โดยตรง** ฐานข้อมูลเก็บเฉพาะข้อความแจ้งส่งและลิงก์ไฟล์ (ตาราง `work_submissions`)
- แอดมินตั้งโฟลเดอร์ปลายทางที่ `/admin/drive` · ดูรายการ/ใครยังไม่ส่งที่ `/admin/submissions`
- ติดตั้ง: (1) รัน `supabase/schema_v5.sql` (2) ตั้งค่า Service Account ตามด้านล่าง
- **ตั้งค่าอัปโหลดอัตโนมัติ:** Google Cloud Console → สร้างโปรเจกต์ → เปิด *Google Drive API* → IAM → Service Accounts → สร้างบัญชี → Keys → Add key (JSON) → ใส่ `client_email` ใน `GOOGLE_SERVICE_ACCOUNT_EMAIL` และ `private_key` ใน `GOOGLE_SERVICE_ACCOUNT_KEY` (Vercel → Environment Variables แล้ว Redeploy) → แชร์โฟลเดอร์ส่งงานให้อีเมลของ Service Account เป็น **ผู้แก้ไข** — ควรใช้ **Shared Drive** ของโรงเรียน เพราะไฟล์ที่อัปโหลดจะเป็นของ Service Account (โควตาเดี่ยวของบัญชีนั้น)
- ถ้ายังไม่ตั้งค่า Service Account ฟอร์มจะทำงานโหมดสำรอง: ครูอัปโหลดไฟล์ใน Drive เอง แล้วกรอกชื่อไฟล์ในแบบแจ้งส่ง

## กลุ่มสาระ/อีเมลของผู้ใช้ + ผู้รับผิดชอบคำร้อง + แจ้งเตือนอีเมล (v6)
1. รัน `supabase/schema_v6.sql` ใน SQL Editor (ต่อจาก schema_v5.sql) แล้ว `npm install` (เพิ่มแพ็กเกจ nodemailer)
2. ตั้ง env สำหรับส่งอีเมล: `SMTP_USER`, `SMTP_PASS` (Gmail ใช้ App Password) และ `SITE_URL` (ไม่บังคับ) ดู `.env.example` แล้ว Redeploy
3. **/admin/users** — ฟอร์มเพิ่มบัญชีมีช่อง “กลุ่มสาระการเรียนรู้” (บังคับ) และ “อีเมล” (ไม่บังคับ) · นำเข้าหลายคนใช้รูปแบบ
   `เลขบัตร, ชื่อ-สกุล, วันเกิด, สิทธิ์(ว่าง=teacher), กลุ่มสาระ, อีเมล` · ผู้ใช้เดิมแก้กลุ่มสาระ/อีเมลได้ที่คอลัมน์ “กลุ่มสาระ / อีเมลแจ้งเตือน”
   (บัญชีเลขบัตรใช้ช่องอีเมลนี้รับแจ้งเตือน เพราะอีเมลล็อกอินเป็นค่าแฮชภายใน)
4. **/admin/requests → 👤 ผู้รับผิดชอบคำร้อง** (admin เท่านั้น) — เลือก ประเภทคำร้อง + ระดับชั้น (เลือกได้หลายระดับ หรือ “ทุกระดับ”) + ครูผู้รับผิดชอบ
   กติกาของระดับชั้นเฉพาะมาก่อน ถ้าไม่มีจึงใช้ “ทุกระดับ”
5. นักเรียนยื่นคำร้อง (ฟอร์มมีช่อง “ระดับชั้น” เพิ่มเข้ามา — ถ้าไม่เลือกระบบเดาจากช่องชั้น/ห้อง เช่น ม.6/2) → ระบบบันทึกผู้รับผิดชอบไว้ที่คำร้อง
